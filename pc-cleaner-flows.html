pc-cleaner — 処理フロー

パターン別の処理ロジック想定 / 走査 → 判定支援 → プレビュー → ゴミ箱削除

core ロジック Safe（既定ON） Caution（既定OFF） Review（確認前提） ゴミ箱削除（既定）
1

ワンクリック掃除（Safe のみ・最短動線）

何も考えずに安全なファイルだけ掃除したいケース。起動直後の既定状態がそのまま実行できる。

起動・設定読込 config.rs

%APPDATA%\cleaner\config.json を読む。前回の rule_prefs と use_trash=true を復元。

↓

プラットフォーム解決 platform/windows.rs

KnownDir の抽象キーを実パスへ解決。needs_admin=true のルールは当面フィルタ除外。

↓

走査・集計 scan.rs

Safe ルールの基点だけを並列走査。サイズ・件数・更新日時・age_days を集計。進捗を通知。

↓

既定選択 Safe → selected=ON

安全度 Safe のエントリを自動でチェック済みに。ユーザーは確認するだけ。

↓

プレビュー → 実行 delete.rs

解放容量を提示し、確定で to_trash() にてゴミ箱送り。誤りは復旧可能。

最短動線。判定をツールが肩代わりしているため、ユーザーの意思決定は「確定」の1回だけ。

2

手動レビュー（Caution / Review を吟味）

既定OFFの候補を判断材料を見ながら選ぶケース。判定支援ロジックの主戦場。

全ルール走査 scan.rs

Safe / Caution / Review すべてを走査し、各エントリにメタ情報を付与。

↓

推奨の動的補正 recommend.rs

純粋関数 recommend(entry, rule) が状況で上書き。理由を reason に格納。

↓
エントリごとに推奨を判定（安全度 × 経過日数 × 使用中の可能性）

Safe

既定ON。reason=「再生成される一時領域」

Caution

180日超のログは推奨ON寄り。注意色で表示。

Review

既定OFF。ユーザーが中身を開いて確認する前提。

↓

ユーザーが微調整 GUI: チェックボックス一覧

サイズ・age_days・由来ルール・reason を見て選択を増減。白紙選択ではない。

↓

プレビュー → ゴミ箱削除 delete.rs

選択分の解放容量を再集計し、確定でゴミ箱送り。

「一覧だけでは判定できない」への回答。age_days と reason が判断を後押しする。

3

ドライラン（CLI・自動化 / 消さずに確認）

薄いCLIで挙動を検証、または定期実行で「何が消える予定か」だけ見るケース。削除は起きない。

cleaner scan または cleaner clean --dry-run

CLI は明示解除しない限り消さない。dry_run が既定的挙動。

↓

走査＋推奨（GUIと同じcore） scan / recommend

ロジックは共通。CLI/GUI で結果が一致する。

↓

一覧出力（削除なし）

ルール・パス・サイズ・age_days・推奨可否・合計解放見込みを標準出力へ。

↓

明示実行 → cleaner clean

ゴミ箱削除を実行。

完全削除 → --permanent

明示オプション時のみ。復旧不可のため要確認。

core が UI 非依存なので、CLI で固めた挙動がそのまま GUI に乗る。自動化にも耐える。

4

管理者権限領域（将来対応の分岐）

初版スコープ外。構造だけ用意し、有効化は後から。フィルタで安全に除外しておく。

走査時に権限判定 platform.requires_admin()

C:\Windows\Temp 等は needs_admin=true。

↓
昇格権限を持っているか？

初版：除外

候補から外し、一覧に「将来対応」と表示。事故を防ぐ。

将来：昇格して対象化

needs_admin ルールを有効化。構造は変えずに後付け。

同じ仕組みで他OS（macOS/Linux）の platform 実装も追加できる。

core（走査・推奨・削除・設定）は UI 非依存。Windows 固有は platform/windows.rs に隔離。 削除は既定でゴミ箱経由・ドライラン既定・許可リスト方式。
